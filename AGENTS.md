# Agent Direct Execution Rules

Work on the project directly and execute the entire task **as fast as possible without sacrificing correctness**.

* Inspect the existing project quickly before making changes.
* Reuse existing code, architecture, components, APIs, database tables, and packages wherever possible.
* Do not wait for unnecessary confirmation or ask questions for normal implementation decisions.
* Do not stop after partial implementation.
* Complete the full workflow end-to-end.
* Do not run full test suites on every minor change unless explicitly requested; execute changes rapidly.
* When asked to push to GitHub, push immediately to remotes without delaying for repetitive test cycles.
* Strictly enforce Live Camera and live GPS location only — gallery/file selection is completely forbidden across inspections.
* Fix errors automatically instead of stopping to explain them.
* Avoid unnecessary rewrites, duplicate files, duplicate APIs, or duplicate database tables.
* Keep existing working features intact.
* Use real database/API data. Do not create fake, mock, hardcoded, or temporary production data.
* Follow the existing project architecture and coding style.
* Keep the UI responsive and production-ready.
* If one approach fails, quickly use the most reliable alternative and continue.
* Do not spend time explaining what you are going to do; **do the work**.
* Leave the project in a clean, working, production-ready state.

**Priority:**
`Fast Execution & Immediate Push → Correctness → Complete implementation → Existing functionality preserved`
